# Google 側の設定手順

参加者どうしで発言を受け渡し、翻訳するためのプログラムを、Google（Apps Script）に置く手順です。
最初に1回だけ行います。所要時間は10分ほどです。

- パソコンで作業してください（スマートフォンでは操作しにくい画面があります）。
- 画面の文言は、Google 側の更新で少し変わることがあります。違っていたら、近い意味のものを選んでください。
- 翻訳には、Apps Script に最初から入っている Google 翻訳を使います。キーの取得や、お金の登録は要りません。
- ルームを作れるのは、**合言葉**を知っている人だけです。合言葉は、手順2でプログラムが作って表示します。QRコードやリンクから参加する人には、合言葉は要りません。

## 用意するもの

- プログラムを置く Google アカウント（個人のアカウントをおすすめします）
- 貼り付けるプログラム（`gas/Code.gs` の中身。テキストファイルで別に受け取っている場合は、そちらを使います）

## 0. 作業用のブラウザの窓を用意する

Google アカウントを2つ以上、同時にログインしていると、途中の画面が開けなかったり、エラーになったりすることがあります。
そこで、**プログラムを置くアカウントだけ**でログインした窓で作業します。

1. Chrome の右上の「︙」→「新しいシークレット ウィンドウ」を押します（Edge は「新しい InPrivate ウィンドウ」、Safari は「新規プライベートウインドウ」）。
2. その窓で <https://accounts.google.com> を開き、プログラムを置く Google アカウントでログインします。
3. このあとの手順1〜3は、すべてこの窓の中で行います。

## 1. プログラムを貼り付ける

1. <https://script.new> を開きます。プログラムを書く画面が開きます。
2. 左上の「無題のプロジェクト」を押して、名前を付けます（例：`通訳ルーム`）。
3. 最初から入っている `function myFunction() { ... }` を、すべて消します（画面の中を1回押してから、Ctrl+A → Delete。Mac は ⌘+A → Delete）。
4. 貼り付けるプログラムの中身をすべてコピーして、貼り付けます（Ctrl+V。Mac は ⌘+V）。
5. 上の「保存」（フロッピーディスクの絵）を押します（Ctrl+S でも保存できます）。

## 2. 翻訳を確かめて、合言葉を受け取る

1. 画面の上のほうにある、関数名を選ぶ欄（「実行」「デバッグ」の右）で `setup` を選びます。
2. 「実行」を押します。
3. 画面の下の「実行ログ」に、次のように出れば成功です。

   ```
   翻訳は動いています（Google 翻訳）。「ご質問があれば、何でもどうぞ。」→ （英語の訳）
   ルームを作るための合言葉：abcde-fghjk
   （合言葉は、ルームを作る人だけが使います。参加する人には伝えないでください）
   ```

4. 2行目の合言葉（上の例では `abcde-fghjk` の部分。実際の文字は、ここで作られたものになります）を控えます。
   あとで、サイトでルームを作るときに入力します。

`setup` は何度実行しても、合言葉は変わりません。合言葉を忘れたときは、もう一度 `setup` を実行すると表示されます。

このプログラムは、許可の要らない機能だけで作ってあるので、許可を求める画面は出ないはずです。
もし「承認が必要です」と出た場合は、次のように進めてください。

1. 「権限を確認」を押す。
2. プログラムを置く Google アカウントを選ぶ。
3. 「このアプリは Google で確認されていません」と出たら、左下の「詳細」→ いちばん下の「（プロジェクト名）（安全ではないページ）に移動」を押す。
4. 「許可」または「続行」を押す。

## 3. ウェブアプリとして公開する

1. Apps Script の画面の右上にある「デプロイ」→「新しいデプロイ」を押します。
2. 「種類の選択」の右にある歯車を押して、「ウェブアプリ」を選びます。
3. 次のように設定します。
   - 説明：何でもかまいません（例：`通訳ルーム`）
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」を押します。
5. 「ウェブアプリ」の URL（`https://script.google.com/macros/s/……/exec`）が表示されます。「コピー」を押して控えます。
6. 新しいタブでその URL を開きます。`"version":"0.2.0"` と `"message":"通訳ルームの中継プログラムは動いています。"` を含む短い文字が表示されれば成功です。
   `message` に「合言葉が、まだありません」と続いている場合は、手順2（`setup` の実行）がまだです。
7. **Google にログインしていない窓**でも、同じ URL を開いてみます（作業用とは別に、もう1つシークレット ウィンドウを開くか、スマートフォンで開きます）。同じ文字が表示されれば、参加者も使えます。Google のログイン画面が出る場合は、下の「うまくいかないとき」を見てください。

「アクセスできるユーザー」を「全員」にするのは、参加者が Google アカウントなしで使えるようにするためです。
このプログラムが扱うのは、ルームの中の発言と訳だけです。あなたの Google アカウントのメール・ファイル・連絡先などにはふれません。

## 4. サイトに URL を入れる

サイトの `config.js` の次の行の `""` の中に、手順3で控えた URL を入れます。

```js
apiUrl: "",
```

↓

```js
apiUrl: "https://script.google.com/macros/s/……/exec",
```

GitHub の画面で直すときは、次の順に押します。

1. リポジトリの `config.js` を開く。
2. 右上の鉛筆の絵（Edit this file）を押す。
3. `apiUrl: "",` の `""` の中に URL を貼り付ける。
4. 右上の「Commit changes…」を押す。
5. 出てきた窓の「Commit changes」を押す。

数分たつと、公開中のサイトに反映されます。
URL が入っていないか、形が正しくないあいだは、サイトの最初のページに赤い枠で「設定の確認」と表示されます。

## 5. 動作を確かめる

自動のテストは、Google の「まね」をするプログラムと、声の聞き取りの「まね」を相手に行っています。
**Google の実物と、実物のスマートフォンでの確認は、ここで初めて行います。** 人に使ってもらう前に、必ず行ってください。

1. パソコンでサイトを開き、「日本語」を選び、「合言葉」の欄に手順2で控えた合言葉を入れて、「ルームを作って入る」を押します。QRコードが出ます。
   合言葉は、その端末（ブラウザ）に保存されます。次からは入力しなくても、ルームを作れます。
2. スマートフォンでQRコードを読み取り、別の言語（English など）を選んで「Join」を押します。
3. パソコンの画面の上に、2人の名前が並ぶことを確かめます。
4. パソコンで文字を打って送ります。数秒のうちに、スマートフォンに訳と原文が出て、訳が読み上げられることを確かめます。
5. スマートフォンでマイクのボタンを押し、「マイクの使用を許可しますか」と出たら許可して、ひとこと話します。話し終えると自動で送られ、パソコンに訳が出ることを確かめます。
6. iPhone と Android の両方の参加者がいる場合は、それぞれの機種で手順2〜5を行います。
7. パソコンで「招待」を押し、いちばん下の小さな文字（例：`v0.2.0 · 2 · 850 ms`）を見ます。左から、版・部屋にいる人数・Google 側の返事にかかった時間です。返事の時間が2秒（2000 ms）をこえることが多い場合は、訳が届くのも遅くなります。

うまくいかないところがあったら、「何番で、画面に何と出たか」を控えてください。

## プログラムを新しくしたとき

プログラムを貼りかえて保存しただけでは、公開中のものは変わりません。次の操作をします。

1. Apps Script の画面で、プログラムをすべて貼りかえて保存します。
2. 合言葉をまだ受け取っていない場合は、関数 `setup` を選んで「実行」を押し、「実行ログ」の合言葉を控えます（手順2と同じです）。
3. 右上の「デプロイ」→「デプロイを管理」を押します。
4. 右上の鉛筆の絵（編集）を押します。
5. 「バージョン」を「新バージョン」に変えて、「デプロイ」を押します。
6. ウェブアプリの URL（`https://script.google.com/macros/s/……/exec`）をブラウザで開き、`"version"` が新しいプログラムの版（いまは `0.2.0`）になっていることを確かめます。前の版のままなら、手順3〜5がまだ済んでいません。

この方法なら、URL は変わりません（「新しいデプロイ」を選ぶと URL が変わってしまうので、使いません）。
合言葉も、プログラムを貼りかえただけでは変わりません。

## 合言葉について

- **だれに必要か**：ルームを作る人（主催者）だけです。参加する人は、QRコードを読み取るだけで入れます。合言葉は、QRコードやリンクには入りません。
- **どこに保存されるか**：ルームを作った端末のブラウザに保存され、次からは入力なしでルームを作れます。保存されるのは、その端末の、そのブラウザの中だけです（`https://（GitHubのユーザー名）.github.io/` で始まるサイトが共通で使う保存場所に入ります）。
- **入力するとき**：入力した文字は、画面にそのまま表示されます。ほかの人に画面を見られない場所で入力してください。一度入力すれば、その端末では、次から入力は要りません。
- **別の端末で主催するとき**：その端末でも、一度だけ合言葉を入れます。入れ方は2つあります。
  - 新しくルームを作るとき：サイトの最初のページの「合言葉」の欄に入れて、「ルームを作って入る」を押す。
  - すでにあるルームに入っているとき：「招待」を押し、「この端末で主催する（合言葉を入れる）」を押して、合言葉を入れ、「決定」を押す。
- **もう一度見たいとき**：Apps Script の画面で、関数 `setup` を選んで「実行」を押すと、「実行ログ」に表示されます。
- **変えたいとき**（ほかの人に知られたかもしれないとき）：関数 `newPassword` を選んで「実行」を押すと、新しい合言葉が「実行ログ」に表示されます。古い合言葉は使えなくなります。公開し直す必要はありません。
  古い合言葉を保存していた端末には、「合言葉が変わっています」と表示されます。「招待」を押し、「この端末で主催する（合言葉を入れる）」から、新しい合言葉を入れてください。
- **ルームが開いている時間**：ルームは、合言葉を入れた端末（主催者の端末）で、ルームの画面が開いているあいだ、開いています。主催者の端末が出るか、画面を消したり別のアプリに切りかえたりしたままにすると、2時間で自動で閉じます。主催者の端末がルームの画面にもどる（同じリンクから入り直す）と、また開きます。発言は、最長6時間は残っています。
- **QRコードを印刷して使うとき**：ルームを作ったあとのリンク（QRコード）は、あとの日にも使えます。当日は、主催者がそのリンクを開いて入ってください。主催者が入る前に読み取った人には「このルームは、いまは開かれていません」と表示され、主催者が入ると自動でつながります（数秒。2分より長く待っていた人は、10秒ほどかかることがあります）。

## 訳の質を上げたいとき（Gemini を足す）

Google 翻訳は、1文ずつ訳すしくみで、会話の流れまでは見ません。
`gas/Gemini.gs` を足すと、Gemini が直前の発言の流れを見ながら、通訳の口調で訳します。
Gemini でうまく訳せなかったときは、自動で Google 翻訳にもどります。なくても動くので、必要になってからで十分です。

1. <https://aistudio.google.com/apikey> を開き、キーを作ってコピーします（「Create API key」）。無料の枠があります。
   無料の枠では、送った文が Google の製品の改善に使われます。有料の枠に切りかえると、使われません。
2. Apps Script の画面の左で、「ファイル」の右の「＋」→「スクリプト」を押し、名前を `Gemini` にして、`gas/Gemini.gs` の中身を貼り付けて保存します。
3. 左側の「プロジェクトの設定」（歯車の絵）を押し、「スクリプト プロパティ」の「スクリプト プロパティを追加」を押します。
   「プロパティ」に `GEMINI_API_KEY`、「値」にコピーしたキーを入れて、「スクリプト プロパティを保存」を押します。
4. 関数 `setup` を実行します。このときは「承認が必要です」と出るので、手順2の下に書いた順に許可します（外のサービスへ接続する許可です）。
   「実行ログ」に `翻訳は動いています（Gemini）。…` と出れば成功です。
5. 「プログラムを新しくしたとき」の手順3〜5で、新バージョンとして公開し直します。

## 知っておくこと

- **発言が残る時間**：発言と訳は、Google 側に最長6時間だけ置かれ、そのあと自動で消えます。1つのルームに置くのは、新しいほうから40件までです。スプレッドシートなどには保存しません。
- **翻訳の回数**：Google 翻訳は、1日 5,000 回までです（訳す言語1つにつき1回と数えます。3つの言語の人がいる部屋では、発言1つで2回）。こえると、その日は訳が付かなくなります。
- **人数の目安**：参加者の端末は、数秒おきに Google 側へ新しい発言を取りに行きます。Google 側が同時にこなせる数には上限（30）があるので、1つのルームに同時に入るのは **30人ほどまで**を目安にしてください。人数が増えると、自動で取りに行く間隔が広がり、訳が届くのが少し遅くなります。実際の上限は、試してみないと分かりません。
- **だれがルームを作れるか**：合言葉を知っている人だけです。サイトの最初のページを開いただけの人は、ルームを作れません。
- **だれが入れるか**：開いているルームのリンク（QRコード）を知っている人は、だれでも入れます。ルームの名前は、推測できない10文字です。
- **履歴を消せる人**：合言葉を入れた端末だけが、「招待」の中の「履歴を消す」を使えます。
- **ルームに入った人ができること**：ルームに入った人は、ほかの人と同じ表示名を名乗って発言することもできます。その場にいる人どうしで使うことを前提にしています。また、ルームに入った人が大量に発言しつづけると、その日の翻訳の回数を使い切ることがあります（1つのルームで受けつける発言は、1分に20件までです）。すぐに止めたいときは、Apps Script の「デプロイ」→「デプロイを管理」で、デプロイを選んで「アーカイブ」を押します。
- **声の聞き取り**：ブラウザの機能を使うので、端末やブラウザによって、使えたり使えなかったりします。使えない端末では、マイクのボタンが出ません（キーボードから入力できます）。LINE などのアプリの中で開いたページでは、使えないことが多いです。Safari や Chrome で開いてください。

## うまくいかないとき

| こうなったら | 確かめること |
| --- | --- |
| Apps Script の画面が開かない／「リダイレクトが繰り返し行われました」「問題が発生しました」などと出る | Google アカウントを2つ以上ログインしているときに起こります。手順0のとおり、シークレット ウィンドウで、プログラムを置くアカウントだけでログインしてやり直してください。 |
| 手順2で「翻訳の試しに失敗しました」と出る | 少し待ってから、もう一度 `setup` を実行してください。何度やっても出る場合は、「実行ログ」の文をそのまま控えてください。 |
| 手順3で「全員」が選べない | 大学や組織の Google アカウントでは、組織の外への公開が止められていることがあります。個人の Google アカウントで手順0からやり直してください。 |
| 手順3-6・3-7で Google のログイン画面が出る | 「アクセスできるユーザー」が「全員」になっていません。「デプロイを管理」→ 鉛筆 → 設定を直して「デプロイ」。組織のアカウントで直らない場合は、個人の Google アカウントで手順0からやり直してください。 |
| URL が `https://script.google.com/a/macros/（組織名）/s/……/exec` の形になっている | 組織の Google アカウントで作ると、この形になることがあります。そのまま `config.js` に入れてかまいません（サイトの側で、ログインなしで使える形に読みかえます）。そのうえで、手順3-7の確認を必ず行ってください。 |
| ルームを作ろうとすると「合言葉がちがいます」と出る | 手順2で控えた合言葉を、もう一度確かめてください（大文字・小文字と「-」のあるなしは、どちらでもかまいません。数字の 0 と 1、英字の l と o は使われていません）。分からなくなったときは、Apps Script の画面で `setup` を実行すると表示されます。 |
| 「Google側で、合言葉がまだ作られていません」と出る | Apps Script の画面で、関数 `setup` を選んで「実行」を押してください（手順2）。 |
| 「Google側のプログラムが古いままです」と出る | プログラムを貼りかえたあとの、公開し直す操作がまだです。「プログラムを新しくしたとき」の手順3〜5を行ってください。 |
| 参加した人の画面に「このルームは、いまは開かれていません」と出る | 主催者（合言葉を入れた端末）が、まだそのルームに入っていないか、出てから2時間以上たっています。主催者の端末で、同じリンクを開いて入ってください。参加した人の画面も、数秒から10秒ほどで自動でつながります。 |
| 主催者の端末に「このルームは、いまは開かれていません」と、その理由（「Google側に接続できませんでした」など）が出る | 主催者の端末から、ルームを開く連絡が届いていません。電波を確かめて、その下の「もう一度」を押してください。 |
| 主催者の端末に「合言葉が変わっています」と出る | 合言葉を作り直した（`newPassword` を実行した）あとです。「招待」を押し、「この端末で主催する（合言葉を入れる）」から、新しい合言葉を入れてください。 |
| サイトの最初のページに「設定の確認」と出る | `config.js` の `apiUrl` が空か、URL の形がちがいます（`https://script.google.com/macros/s/` で始まり `/exec` で終わる形）。書きかえた直後は、反映まで数分かかります。 |
| ルームに入ると「ルームに接続できませんでした」と出る | 手順3-7の確認をもう一度行ってください。ログインしていない窓で URL を開いて文字が出ない場合は、デプロイの設定を直します。 |
| 発言は届くが、訳が付かない（「翻訳できませんでした」と出る） | その日の翻訳の回数（5,000回）をこえた可能性があります。翌日には元にもどります。続けて起こる場合は、Apps Script の画面で関数 `setup` を実行して、「実行ログ」に訳が出るか、出ない場合は何と書かれているかを確かめてください。 |
| マイクのボタンが出ない | その端末・ブラウザでは、声の聞き取りが使えません。Safari（iPhone）か Chrome（Android・パソコン）で開いてください。それでも出ないときは、キーボードのマイクキーで話すか、文字で入力します。 |
| マイクを押すと「マイクを使えません」と出る | ブラウザの設定で、このサイトのマイクが「許可しない」になっています。アドレスの欄の左の印（鍵や「ぁあ」）から、マイクを「許可」に変えて、ページを開き直してください。iPhone では、キーボードの音声入力がオフになっていると使えないことがあります（「設定」→「一般」→「キーボード」→「音声入力」をオンにします）。 |
| 訳が読み上げられない | 画面の右上のスピーカーのボタンが、色のついた状態（オン）になっているか、端末の音量と消音スイッチを確かめてください。スピーカーのボタンが出ない端末では、読み上げが使えません。 |
